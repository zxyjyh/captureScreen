# captureScreen

每 3 分钟截一次屏，用多模态模型读懂屏幕上的**内容**，沉淀成可检索、可回溯的个人工作记忆。

## 项目目标

**做一个「第二大脑的输入端」——自动捕获我在电脑上经历过的一切，让过去的自己可被检索、可被追问。**

人的工作记忆只有几分钟，笔记依赖自觉，而屏幕是唯一 100% 忠实记录认知轨迹的地方。这个项目要把这条被浪费掉的数据流，变成三种能力：

1. **找回**：任何我看过、写过、想过的东西，都能用自然语言问出来
   —— 「上周看的那篇讲 FDE 的文章说了什么」「上次这个报错我是怎么修的」
2. **重建**：还原我当时的思维路径，不只是结果
   —— 我为什么从 A 跳到 B，卡在哪一步，试了几条路
3. **合成**：把碎片压缩成长周期的意义
   —— 这个月我真正在推进的是什么，注意力实际投在了哪三件事上

### 一句话取舍标准

> 当一个功能不能让「找回 / 重建 / 合成」中的任何一项变强时，它就不该做。

## 明确的非目标

| 不做 | 为什么 |
|---|---|
| 时间统计 / 效率打分 | RescueTime、Timing 做得更好，且 app 时长是最没信息量的一维数据 |
| 自我监工、生产力说教 | 「减少应用切换」这类正确的废话没有决策价值，只会让人关掉它 |
| 多用户、云端、SaaS 化 | 单人本地工具。数据永不出本机是这个项目成立的前提 |
| 实时提醒 / 打断 | 它是记忆，不是闹钟。所有价值在事后回看时兑现 |

## 成功标准

这个项目算成功，当且仅当以下三条同时为真：

1. **被真实使用**：连续运行 30 天以上，且我每周主动打开看板 / 提问 ≥ 3 次
   （反指标：`reports/` 持续堆积但无人访问 —— 这是当前最大的失败风险）
2. **答得出记不住的事**：随机抽 10 个「两周前我在干什么 / 那个东西在哪」的问题，能答对 ≥ 7 个，且答案带得出具体证据（截图时间 + 原文片段）
3. **不引起心理负担**：隐私过滤可靠到我不需要在敏感操作前手动暂停它

## 当前状态与差距

已有：定时截图（capture.py）、逐时段视觉分析（analyze.py）、日/周期汇总（summarize.py / period_summary.py）、看板（dashboard.py + static/）、RAG 检索骨架（rag.py / query.py，`rag.enabled: false` 尚未启用）。

对照目标的主要差距：

- **找回能力未打通** —— RAG 是关闭的，检索目前是这个项目的核心能力却还没上线。这是第一优先级。
- **分析 prompt 偏「点评」而非「记录」** —— `analyze.py` 里的「亮点 / 可改进」板块产出说教内容，与非目标冲突，应替换为更利于检索的结构化事实抽取（实体、文件名、URL、待办、未解决的问题）。
- **缺长周期合成** —— 有日报周报，但没有「跨月主线提取」，第 3 项能力尚不存在。
- **报告只增不减** —— 缺少「过期报告降级为向量 + 摘要」的生命周期，长期会淹没自己。
