# 拾遗 · Gleaner

> 补阙拾遗——唐代的官职，职责是记录别人漏掉的事。
> 英文 Gleaner 出自米勒的《拾穗者》：收割之后，捡起地里剩下的麦穗。
>
> **你的工作日是那场收割，这个工具捡的是掉在地上的那部分。**

按事件截屏，用操作系统本地能力把屏幕上的字免费取出来，
再让模型只负责理解 —— 沉淀成可检索、可回溯的个人工作记忆。

## 项目目标

**做一个「第二大脑的输入端」——自动捕获我在电脑上经历过的一切，让过去的自己可被检索、可被追问。**

人的工作记忆只有几分钟，笔记依赖自觉，而屏幕是唯一 100% 忠实记录认知轨迹的地方。这个项目要把这条被浪费掉的数据流，变成三种能力：

1. **找回**：任何我看过、写过、想过的东西，都能用自然语言问出来
   —— 「上周看的那篇讲 FDE 的文章说了什么」「上次这个报错我是怎么修的」
2. **重建**：还原我当时的思维路径，不只是结果
   —— 我为什么从 A 跳到 B，卡在哪一步，试了几条路
3. **合成**：把碎片压缩成长周期的意义
   —— 这个月我真正在推进的是什么，注意力实际投在了哪三件事上

### 一句话取舍标准

> 当一个功能不能让「找回 / 重建 / 合成」中的任何一项变强时，它就不该做。

## 安装

只支持 macOS —— 无障碍树和 Vision OCR 都是系统能力，换平台要重写这两块。

```bash
git clone https://github.com/zxyjyh/gleaner.git
cd gleaner
bash install.sh
```

脚本会建 venv、装依赖、把 API key 写进 `.env`、注册开机自启的后台服务，最后跑一遍自检。

装完还要手动授两个权限。**macOS 的权限授予对象是可执行文件，不是项目目录**，所以要加的是 venv 里那个 python（`install.sh` 会把完整路径打出来）：

| 权限 | 没有它会怎样 |
|---|---|
| 屏幕录制 | 只截到桌面壁纸，看不见任何窗口 |
| 辅助功能 | 读不到窗口内文本，退回 OCR —— 更慢、更不准 |

两个都是**静默失败**：程序照常运行，只是采不到东西。所以任何时候都可以跑自检确认：

```bash
venv/bin/python doctor.py
```

接进 Claude Code 之后，就能直接问「上周三下午我在干什么」「那个 40164 报错我后来是怎么解的」：

```bash
claude mcp add gleaner -- "$PWD/venv/bin/python" "$PWD/mcp_server.py"
```

| 命令 | 作用 |
|---|---|
| `bash status.sh` | 看运行状态与今日采集量 |
| `bash stop.sh` / `bash start.sh` | 停止 / 启动 |
| `tail -f capture.log` | 实时日志 |

### 数据在哪

全部在本机，不出网 —— 唯一的出网调用是把**文本**发给模型做分析。

```
screenshots/YYYY-MM-DD/HH-MM-SS.png    截图
                      /HH-MM-SS.txt    无障碍树抓的文本（本地免费）
                      /HH-MM-SS.ocr    OCR 兜底结果（本地免费）
reports/YYYY-MM-DD/HH.md               每小时的分析报告
```

`screenshots/` 和 `reports/` 都在 `.gitignore` 里，不会被误提交。

### 隐私

这个工具录你的屏幕。默认怀疑它是对的，所以下面把能做的和做不到的都写清楚。

**唯一出网的动作**是每小时把文本发给模型做分析。截图本身从不上传。
向量检索用的是本地模型（chromadb 自带），不出网。

#### 三道闸

| 闸 | 配置 | 作用 |
|---|---|---|
| 不采集 | `privacy.skip_keywords` | 命中窗口标题就整次跳过，截图都不产生。密码管理器、银行、无痕窗口 |
| 采集不外发 | `privacy.local_only_apps` | 照常落盘、本地可搜，**永不发给模型** |
| 出网前脱敏 | `redact.local.yaml` | 人名、公司名换成 `【人名1】`，报告生成后换回真名 |

脱敏做在 `llm.py` 的出网收口，不在各调用点 —— 调用点有七个，漏一个就前功尽弃
（开发时就漏过：报告在分析阶段脱敏后还原成真名，转手又被向量索引发出去了）。
邮箱、手机号、长串数字由代码自动抹掉，且**不还原**。

术语表怎么填：

```bash
venv/bin/python redact.py     # 从你自己的本地数据里找候选，人工确认后粘进去
```

它按「@提及」和「发言人:」的结构匹配，所以繁体简体都能捞到 ——
屏幕上是什么样就捞到什么样。一定有误报，由你过一遍再决定。

#### 删除数据

看板里有「存储管理」：按日期勾选，两个按钮 ——

- **只删图片，保留文本**：省下几乎全部空间（图片占 99.9%），报告和检索照常
- **全部删除**：截图、文本、报告、向量索引一起删

命令行同样可以，默认只预览，加 `--yes` 才真删：

```bash
venv/bin/python purge.py                        # 看看有什么
venv/bin/python purge.py --day 2026-09-01 --yes
venv/bin/python purge.py --before 2026-09-01 --yes
venv/bin/python purge.py --all --yes
```

删报告时会一并清掉它的向量。**这一步最容易漏**：报告删了向量还在，
`recall` 照样把原文捞出来。

#### 磁盘小怎么办

实测图片占 **99.8%**、文本占 **0.2%** —— 文本是图片的 1/600。
所以先砍图片：它被抽成文本之后，剩下的用途只有人工翻看，
而「上个月那天我在干什么」这种问题，文本答得了。

前提是**每张图都已经被抽成文本**。这一步原本有漏洞：`.ocr` 只在分析时
按需生成，而分析前会去重、还封顶 30 帧 —— 被筛掉的帧从来没被 OCR 过，
配上图片保留期就永久消失了（实测 162 张里有 49 张属于这种情况）。
现在两道保险：后台每小时补抽，删图之前再兜底抽一次，抽不出来就不删。
`doctor.py` 会报覆盖率。

```yaml
capture:
  image_retention_days: 2   # 超过 2 天只留文本，图片删掉
  max_disk_mb: 2000         # 整个 screenshots 的硬上限
  displays: active          # 只拍前台那块屏，省一半
  image:
    max_width: 1280         # 再降一档，OCR 仍保留 94%
```

`max_disk_mb` 是硬上限：超了先删最旧的图片，还不够才删最旧的文本。
保留期是「多久之前的删掉」，这条是「最多用这么多」——
磁盘紧张时真正需要的是后者。

#### 随时暂停

```bash
bash pause.sh 30    # 暂停 30 分钟，到点自动恢复
bash pause.sh 0     # 立即恢复
```

带过期时间是刻意的：忘记恢复比忘记暂停常见得多，
「关了它然后三周没开」等于这个工具不存在。

#### 数据在本机怎么放

- 目录权限 `700`，文件 `600`，采集进程 `umask 077`
- 截图默认留 7 天，报告留 90 天（`retention_days`），过期自动删
- macOS 的 FileVault 负责静态加密，请确认它是开的：`fdesetup status`

#### 做不到的四件事

写在这里，是因为不写清楚才该被怀疑。

1. **多模态兜底发的是原图，无法脱敏。**
   只在无障碍树和 OCR 都抽不到文字时才走这条路。要彻底避免，
   把相关应用放进 `local_only_apps`，或 `analysis.mode` 保持 `text`。

2. **MCP 工具的结果会进入你的 AI 客户端对话。**
   在 Claude Code 里调 `search_screen`，命中的屏幕原文就成了对话的一部分，
   会发给该客户端的服务商。「四个工具不联网」说的是它们自己不发请求，
   不等于结果不会被转发。

   所以 `local_only_apps` 在工具层也生效：`timeline` 和 `search_screen`
   默认排除这些应用，并注明挡了多少条。确需查看时传
   `include_local_only=True`，或直接在本机看板上看 —— 看板不经过任何模型。

   **但按应用过滤挡不住内容转载。** 钉钉的内容被你复制到终端或编辑器里，
   那一帧的应用是终端，就挡不住了。实测过：终端上显示着讨论钉钉的对话，
   搜索照样命中。要挡这一层只能靠脱敏术语表。

3. **屏幕上有别人的隐私。**
   同事的聊天消息、视频会议里的人脸，他们没同意被记录。
   脱敏只处理你列出的名字，处理不了截图里的人脸。
   这不是技术问题 —— 用之前请确认符合你公司的规定。

4. **术语表只挡你列过的词。**
   新同事、新客户、新项目代号都会漏。定期跑一次发现命令。

## 模型后端

| provider | 鉴权 | 说明 |
|---|---|---|
| `claude`（默认） | Claude Code 订阅 | 走 `claude-agent-sdk`，透过 CLI 鉴权，**不需要 API key**。每次调用起一个 CLI 子进程，约 9 秒 |
| `zhipu` | `ZHIPU_API_KEY` | 直连 REST。需要账户余额 |

在 `config.yaml` 的 `api.provider` 切换。

向量检索没有对应的云端接口，一律走 chromadb 自带的本地模型：免费、离线，
也少掉一条出网路径。代价是它以英文训练为主，**中文区分度偏弱**
（实测语义相关 0.58、完全无关 0.52，只差 0.06）。
所以精确检索请用 `search_screen`——那是 grep 原文，不依赖向量。

## 成本

原本每张截图都发给多模态模型，图片 token 比文本贵一个数量级。现在让操作系统先把字免费取出来：

```
改造前   截图 ──────────────→ 多模态模型 → 文本 + 理解
改造后   截图 → 无障碍树/OCR → 文本 → 模型 → 理解
                （本地，零成本）
```

配套的省法还有：相邻帧去重、系统空闲时不截图、按小时批量请求。

## 明确的非目标

| 不做 | 为什么 |
|---|---|
| 时间统计 / 效率打分 | RescueTime、Timing 做得更好，且 app 时长是最没信息量的一维数据 |
| 自我监工、生产力说教 | 「减少应用切换」这类正确的废话没有决策价值，只会让人关掉它 |
| 多用户、云端、SaaS 化 | 单人本地工具。数据永不出本机是这个项目成立的前提 |
| 实时提醒 / 打断 | 它是记忆，不是闹钟。所有价值在事后回看时兑现 |

## 成功标准

这个项目算成功，当且仅当以下三条同时为真：

1. **被真实使用**：连续运行 30 天以上，且我每周主动打开看板 / 提问 ≥ 3 次
   （反指标：`reports/` 持续堆积但无人访问 —— 这是当前最大的失败风险）
2. **答得出记不住的事**：随机抽 10 个「两周前我在干什么 / 那个东西在哪」的问题，能答对 ≥ 7 个，且答案带得出具体证据（截图时间 + 原文片段）
3. **不引起心理负担**：隐私过滤可靠到我不需要在敏感操作前手动暂停它

## 当前状态与差距

已有：

| 环节 | 实现 |
|---|---|
| 采集 | `capture.py` —— 定时截图 + 同时刻抓无障碍树文本，空闲时跳过 |
| 本地抽文本 | `accessibility.py`（无障碍树，主）/ `ocr.py`（Apple Vision，兜底） |
| 分析 | `analyze.py` —— 默认走文本模式，`vision` 保留作对照 |
| 汇总 | `summarize.py` / `period_summary.py` |
| 检索 | `rag.py` / `query.py`，已启用 |
| 访问入口 | `mcp_server.py`（5 个 tool）、`dashboard.py`（看板） |
| 复制资产 | `pipes/` —— 每个目录一份 prompt.md |

对照目标的主要差距：

- **缺长周期合成** —— 有日报周报，但没有「跨月主线提取」，第 3 项能力尚不存在。
- **报告只增不减** —— 缺少「过期报告降级为向量 + 摘要」的生命周期，长期会淹没自己。
- **固定间隔采集** —— 每 3 分钟一次，与实际活动无关。改成事件驱动（切换应用、窗口聚焦、停止输入）能在同样信息量下少截很多张。
- **文本模式未经长期验证** —— 已跑通，但还没和 vision 模式做过并排的产出质量对照。
